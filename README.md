# Nmap-AI

Nmap-AI is a local-first application for authorized network discovery, Nmap scan management, vulnerability triage, telemetry review, and evidence reporting. It stores results from actual Nmap XML or received telemetry; it does not generate sample scan results.

## Modules

- **Dashboard** — recorded hosts, open ports, findings, and recent scan jobs.
- **Network Discovery** — observed host and service inventory; compare completed scans.
- **Scan Management** — inspect scan arguments, run scans only for an explicitly authorized target, import Nmap XML, and cancel running scans.
- **Vulnerability Findings** — catalog correlations with evidence, confidence, validation state, and analyst workflow.
- **Live Traffic** — inspect received events and detection alerts. No packet data is generated by the UI.
- **Reports** — generate and download JSON/PDF summaries from stored records.
- **Settings** — configure scanner details and the CIDR allowlist.

The optional flow classifier is trained on the included CIC-IDS2017 PortScan dataset and can classify sufficiently complete telemetry flows. Its predictions are not proof of compromise and are separate from Nmap vulnerability findings.

## Requirements

- Python 3.12+
- Node.js 20.19+ and npm 10+
- Nmap for active scans (Nmap XML import does not require Nmap to be installed)

## Run locally

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
cp .env.example .env
```

Before starting, replace the API token and password in `.env` with unique values. The backend defaults to loopback (`127.0.0.1`); do not expose it to a network with placeholder credentials.

Start the API:

```bash
source .venv/bin/activate
python main.py
```

Start the web UI in another terminal:

```bash
cd frontend
npm ci
npm run dev
```

Open `http://127.0.0.1:5173`. Sign in with `NMAP_AI_USERNAME` and `NMAP_AI_PASSWORD` from `.env`. The API uses the configured token for protected endpoints.

## Authorized scanning

1. Install Nmap and configure `NMAP_AI_NMAP_PATH` if it is not on `PATH`.
2. Sign in and add only networks you own or have explicit permission to assess under **Settings → Authorized Target CIDR Allowlist**.
3. Use **Scan Management** to inspect the argument preview, confirm the exact target and authorization, then explicitly start the scan.

The application does not schedule scans or select targets automatically. Scan execution uses a structured argument list (not a shell), an allowlist check, explicit operator confirmation, and a timeout. The `safe` Nmap script profile uses the `safe` script category; scan impact still depends on the target and network. Import existing XML when active scanning is not appropriate.

## Telemetry and machine learning

Traffic records appear only after data is sent to `POST /api/v1/traffic/ingest` or to the optional framed TCP listener (`python capture/live_monitor.py`). The listener accepts length-prefixed Ethernet frames; parsing them requires Scapy. It is not a built-in interface sniffer. Configure a separate authorized capture source and keep the listener bound to loopback unless network access is required.

The classifier uses the fixed feature schema in `ml/preprocessing/schema.py`. Incomplete flows are skipped. Reproduce training with:

```bash
source .venv/bin/activate
python -m ml.training.train
```

Evaluation metrics are produced by that run on the offline dataset and should not be treated as a guarantee of live detection accuracy.

## Data and configuration

- `.env` contains local credentials and is ignored by Git.
- SQLite, scan XML/JSON, and generated reports are written under `data/`.
- Model files are generated under `ml/artifacts/`; serialized model files are ignored.
- The CVE catalog is a local correlation source. A match is an analyst lead, not evidence of exploitation.
- The API reference and threat model are in [`docs/`](./docs/).
